# 🏏 CricPoints Arena

A fantasy cricket **prediction game** with an exchange-style interface (Back/Lagai &
Lay/Khai prices, live odds, session markets) plus fair casino mini-games — played
entirely with **virtual points**.

## ⚖️ Design constraints (hard rules of this product)

- **Invite-only registration.** Signing up requires a valid single-use invite
  link/code generated by an admin. There is no admin-issued account / agent /
  downline system — by design. Accounts are always created by their owners via an
  invite; admins never create accounts or set passwords for users.
- **Points are 100% virtual.** They are free, have **no cash value**, and cannot be
  bought, sold, transferred, or withdrawn. Points are earned from the signup bonus,
  the daily bonus, winning predictions, and casino games. That's it.
- **One global welcome-points amount.** The welcome grant is a single platform
  setting (default 10,000, editable by an admin) that applies **uniformly to every
  invite and every new account**. Point amounts are never set per invite or per
  person. There is **no referral system and no point-reward programs**; the daily
  bonus is a uniform, rule-based refill available to everyone.
- **Casino games are genuinely random.** Outcomes come from crypto-grade randomness
  (`crypto.getRandomValues`) and payout tables are published in the UI. Outcomes are
  never rigged or manipulated; the only margin is the disclosed payout gap
  (e.g. coin flip pays 1.9× instead of a fair 2.0×).
- **Admin is content-only.** Admins manage matches, suspend/resume markets, settle
  results, and view users. There are deliberately **no** credit-issuance or bookie
  liability tools.

## Features

- **Auth** — invite-only signup (single-use invite link/code required), login/logout.
  New users get the **global welcome-points amount** (default **10,000**, admin-configurable);
  a **+1,000 daily bonus** is claimable once per calendar day.
- **Matches** — live list from CricAPI when configured, otherwise a built-in
  **Demo Feed**: a ball-by-ball T20 simulator (India vs Pakistan live on first open,
  plus upcoming fixtures and a result). Demo Feed matches tick every ~3 seconds and
  fast-forward while you're away.
- **Odds engine** (`src/lib/odds.ts`, documented in code) — win-probability model:
  pre-match from team ratings; in-play from a resource-based projection
  (runs / wickets / balls / required rate through a logistic). Probabilities convert
  to Back/Lay decimal prices with a published **1.5% margin**. Prices flash
  green/red as they move; markets suspend briefly after a wicket.
- **Markets** — Match Odds plus two session (fancy) markets: first-6-overs and
  first-10-overs totals (Over/Under a line), settled automatically at the milestone.
- **Predictions with correct exchange mechanics** —
  Back: risk = stake, win = stake × (odds − 1).
  Lay: liability = stake × (odds − 1) is reserved from your balance; if the selection
  loses you win the stake, if it wins you lose the liability.
  Cancel any pending prediction before the match ends for a full refund.
  Automatic settlement when a match finishes (ties refund).
- **Leaderboard** — by points balance, plus biggest winners of the last 7 days.
- **Casino (fair, points only)** — Coin Flip (1.9×), Spin Wheel (8 published
  segments, 90% expected return), Dice Over/Exactly/Under 7 (payouts = true odds × 0.95).
- **Admin-lite** — generate/copy single-use **invite links**, list used/unused
  invites, revoke invites, edit the **global welcome-points setting**, add manual
  matches, suspend/resume markets, start matches, force-settle, view registered users.

## Tech

Next.js (App Router, TypeScript) + Tailwind CSS. One data-provider interface
(`src/lib/context.ts`) with two implementations:

| Mode | When | Data |
| --- | --- | --- |
| **Demo Mode** | No Supabase env vars | Everything in browser `localStorage` — local accounts, points, bets, simulator feed. Shows a **Demo Mode** badge. 100% functional. |
| **Supabase Mode** | `NEXT_PUBLIC_SUPABASE_URL` + `NEXT_PUBLIC_SUPABASE_ANON_KEY` set | Supabase Auth + Postgres (`profiles`, `bets`, `casino_plays`, `matches`, `invites`, `platform_settings`). Live matches via the CricAPI route. The ball-by-ball simulator feed is a demo-mode feature; in Supabase mode matches come from CricAPI/admin and settle via feed results or admin force-settle. Session markets need ball-by-ball state, so they're offered on Demo Feed matches. |

## Environment variables

| Variable | Required | Purpose |
| --- | --- | --- |
| `CRICAPI_KEY` | No | Server-side key for live match data (see below). Without it, the Demo Feed is used. |
| `NEXT_PUBLIC_SUPABASE_URL` | Only for Supabase mode | Your Supabase project URL. |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Only for Supabase mode | Your Supabase anon/public key. |
| `NEXT_PUBLIC_ADMIN_EMAILS` | No | Comma-separated emails treated as admins in Supabase mode (UI gate). In Supabase mode also grant `is_admin` in the DB (step 4 below). In Demo Mode, admin is the seeded `admin@cricpoints.demo` account. |
| `ADMIN_EMAILS` | No | Server-side naming kept for parity; the app reads `NEXT_PUBLIC_ADMIN_EMAILS` for the client-side gate. |

Copy `.env.example` to `.env.local` and fill in what you need.

## Supabase setup

1. Create a project at [supabase.com](https://supabase.com).
2. In the project's **SQL Editor**, run the full contents of
   [`supabase/schema.sql`](supabase/schema.sql) (tables, signup trigger that grants
   10,000 welcome points, RLS policies, admin self-promotion guard).
3. (Recommended for a smooth demo) In **Authentication → Providers → Email**, turn
   **off** "Confirm email" so users can log in immediately after signup.
4. Make yourself admin: in the SQL Editor run
   `update public.profiles set is_admin = true where email = 'you@example.com';`
   and add the same email to `NEXT_PUBLIC_ADMIN_EMAILS`.
5. Set `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY` (Project
   Settings → API) in `.env.local`, then restart `npm run dev`.

> Security note: schema policies are demo-grade — balance movements are written by
> the client. For a production launch, move point movements into Postgres RPC
> functions / Edge Functions using the service role.

## CricAPI setup

1. Get a free API key at [cricapi.com](https://cricapi.com) (free tier available).
2. Set `CRICAPI_KEY=...` in `.env.local` (server-side only, never exposed to the
   browser) and restart.
3. The server route `GET /api/matches` fetches `currentMatches`, normalizes it
   into the app's match format, and the UI badges those matches **CRICAPI**.
   If the key is missing or the fetch fails, the app transparently falls back to
   the Demo Feed.

## How the odds move (short version)

- Every selection has a model win probability `p`. Fair odds = `1/p`.
- Published prices: **Back = fair × (1 − 1.5%)**, **Lay = fair × (1 + 1.5%)**.
- In-play, `p` updates on every ball from the projected final total vs the
  target/expected chase total (logistic curve), and session markets price the
  probability of beating the runs line at over 6 / over 10.
- After a wicket, the market suspends for ~2.5 s, like a real exchange.
